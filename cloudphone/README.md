# 云手机（红手指）上跑脚本

怎么用：[USER_GUIDE.md](USER_GUIDE.md)（日常使用、更新、换实例、常见问题）。下面是技术说明。

脚本在云手机**内部**运行：`/data/local/tmp/ip` 里用 proot 跑一个 Alpine Linux（不需要 root，不装任何 App），
里面的 Python 通过手机自己的 adb（`127.0.0.1:5555`）截图和点击，截图 ~0.3 秒。
后台服务 `supervisor.py`（只监听手机本机 `127.0.0.1:8765`）一次跑一个脚本；浮窗 App「星球脚本」可以选脚本、开始、停止、更新。
Mac 只在部署和调试时通过 Tailscale + adb 连手机，命令都在 `cloudphone/cp.sh`。

## 换新实例
1. 手机上：设置 → 关于手机 → 连点版本号 → 系统 → 开发者选项 → 打开 **USB 调试**。
2. 装 Tailscale 并用和 Mac 同一个账号登录，把手机的 100.x 地址写进 `cloudphone/.serial`（例如 `100.104.162.101:5555`）；另一个号的手机写进 `cloudphone/.serial.号名`。
3. Mac 上：`cloudphone/cp.sh all`（装环境、从 GitHub 拉代码、装浮窗、启动服务）；另一个号：`cloudphone/cp.sh -a 号名 all`，它还在手机上记下号名（`/ip/account`）。手机没有 proot 时由 Mac 下载后推过去（有的手机连不上 GitHub 的 raw 文件），Mac 下不到才让手机自己下。
4. 手机上打开游戏登录（同一账号只能在一台设备在线）。

## 日常
- 浮窗：点小圆点 → 选脚本 → 开始。小圆点默认在右上角，随时能拖，运行时变小、半透明的绿色「运行」。脚本看屏幕之前先让浮窗隐身（`AdbDevice.hide_for_look`：广播 `com.ip.panel.HIDE` 10 秒，App 的上限；剩 3 秒时续期），脚本进入等待时（`nap`）用 `show_overlay` 让它回来：小圆点放在哪里都挡不到脚本要认的按钮（守卫弹出的「袭击」按钮曾被它挡住，脚本以为没打开）。隐身期间点击不再每次读窗口，每 10 秒核对一次；隐身没生效时（App 刚重启）照旧在点击的同一条 shell 里先发 HIDE。面板开着时先等最多 12 秒。脚本每分钟广播 `com.ip.panel.HELLO`（浮窗记 3 分钟）；运行中的脚本没报到（旧代码），小圆点就保持点击穿透。
- 手机上的速度：`AdbDevice` 发现自己和手机共用一个目录（脚本跑在手机里，`/ip/tmp`）时，截图改成 `screencap` 写原始画面到那里再直接读（`shot.进程号.raw`，每个进程一个文件，每次截图前先删、退出时删；约 0.23 秒，PNG 经 adb 要 0.4～0.6 秒）；一串连点（`burst`）按 6 秒一段合成 shell 命令（每次点击约 0.12 秒，原来 0.35～0.47 秒；一段不超过一次隐身的时长，也远小于 adb 的超时）；`fortress_fight --pace` 把点击后的固定等待乘以一个系数，脚本跑在手机里时默认 0.6（云手机画面出得比 Mac 的模拟器快），等待时查看舰队的间隔同比缩短。从换装到出击发出，一轮由约 3 分半降到 2 分 10 秒。游戏自己的时间不按系数缩短：动画（买行动点后的提示淡出、页面变暗后恢复、一键配队生效）用固定秒数，点击后等效果出现的时限按秒计（`PRESS_WAIT`、`CONFIRM_WAIT`），不按“看几次”计。连点合成一条命令后几下点击只隔 0.1 秒，碰上页面还没稳定会一起落空：有校验会重试的（页签）和点得很多的（卸装）没关系，「一键配队」没人校验，出过一次装备没装上就出击、0% 回来（原来一下一下点的 204 次换装里没有过）。现在它和卸神器时点预览的三下点击恢复 0.35 秒间隔（`UNCHECKED_TAP_GAP`），配完装备匹配度不到 0.9 就再点一次，还不到就不出击：这次换装留到下一轮（重新卸原主人、重新配），3 轮不行就放弃，把装备装回去。
- 更新：代码推到 GitHub 后，浮窗点「更新」（拉最新代码、更新脚本列表等手机端文件，重启正在跑的脚本；服务本身改了也会重启服务）。
- 脚本出错退出会在 60 秒后自动重启（每小时最多 5 次）；正常结束的和试跑（--dry）的不重启。
- 停止（停止、更新、`cp.sh restart`）给脚本发 SIGTERM：fortress_fight 在下一个安全点退出（两轮之间、换装或出击开始前；换装做到一半就做完或放弃并把装备装回去），最多等 240 秒，超时才 SIGKILL；脚本退出后，它留下的子进程（比如没做完的 adb 点击）也一起结束。万一还是被硬杀在换装中间：换装模式记着上一任装备主人（`fortress_gear.json`），下次开头找不到带装备的船，就在它身上点一键配队把散着的装备收回来。这类状态文件（`cp.sh` 里的 `STATE_FILES`）在重新克隆代码时会保留。
- 手机重启后：点「星球脚本」图标 → 面板里「启动服务」，会接着跑重启前在跑的脚本。
- 号（account）：一个号是一份配置，逻辑相同。手机的 `/ip/account` 里有号名（例如 `gs`）时，服务读 `scripts.号名.json` 作面板的列表，`fortress_fight.py` 用 `pics/mac/zone/loadout_standard_号名.png` 作标准装备图；没有号名、或没有那个名字的文件，用默认的 `scripts.json` 和 `loadout_standard.png`（jx）。`cp.sh -a 号名` 选那个号的手机（地址在 `cloudphone/.serial.号名`），`setup` 带 `-a` 时写号名；让手机回到默认号：`cp.sh -s 地址 sh "rm /ip/account"`。
- 脚本列表在 `cloudphone/phone/scripts.json`：平铺的列表 `[{"group", "id", "name", "args", "restart"?}]`，`group` 是类别（面板一次显示一类），`id` 全文件唯一。保持平铺是为了新旧版本的服务和浮窗都能读。服务会自动加上 `--adb 127.0.0.1:5555 --delay 0`，目前 fortress_fight.py 和 boss_fight.py 支持 `--adb`。
- 世界 Boss（「战斗」类别）：`boss_fight.py --adb` 走 `world_boss.py`（`-d` 钻石模式，`--dry` 只到 Boss 页面，`--max-buys N` 最多买 N 次强力一击，按一次启动计：出错后被服务重新启动的那一次重新数）。流程：主界面「星际玩法」→「星际冒险」列表的世界BOSS「立即前往」→「挑战」→ 战斗页掷骰子（50 颗，点一下掷一颗）→ 骰子掷完再点会弹「购买确认」（卖骰子，只有购买一个按钮，点对话框外面关闭）即结束 → 点礼物盒领礼物（每档弹一次「恭喜获得」，领完礼物盒消失）→「回家」。中途的「美食星系的帮助」是强力一击：2 倍免费、3 倍 20 钻石、4 倍 100 钻石，默认点「免费」，`-d` 点最右边的「购买」。骰子从不购买：主界面的骰子按钮和战斗页的在同一位置，主界面「更多骰子」弹窗里的「购买」和强力一击的长得一样，所以只有认出战斗页（「回家」和它旁边「基础伤害」的问号，拜访别人星球的页面也有同样的「回家」）才掷骰子，只有同一行有「免费」的「购买」才会点。「购买」点了弹窗没关（钻石不够）两次，这一场剩下的强力一击改选「免费」；战斗页上出现点不掉的不认识的弹窗，脚本停下来回主界面，不乱点。模板是 `pics/mac/zone/wb_*.png`（在手机上按参考比例截的纯文字或按钮图），各页面的原图在 `pics/mac/zone/pages/worldboss/`。Boss 只在 11:00–13:00、19:00–21:00 出现，其余时间脚本报告「不在」并正常结束。「好的」（上一场结果页，桌面脚本会先关掉它）在手机上还没遇到过，用的是桌面版的图，匹配 0.9 以上才点。
- 更新的备用线路：git 因为网络拉不动 `github.com`（有的云手机上被限速）时，`update_by_api` 改走 `api.github.com`：取最新提交和它的文件清单，按 git 的内容校验值（blob sha）和手机上的文件逐个比较，只下载不同的，逐个校验后先放临时目录再换进去，提交里已经没有的文件删掉。手机仓库的 HEAD 不动，`/ip/api_version` 记下代码是哪个提交的、当时的 HEAD 是哪个（标签带 `+api`）；HEAD 变了它就作废，git 更新成功时删掉，并把备用线路加过、仓库里已经没有的文件一起删；电脑推来代码后标签回到 git 的。git 因网络失败后 6 小时内直接走备用线路（记在 `/ip/git_blocked`，服务重启也保留；备用线路自己做不了时解除，下次再试 git）；`cp.sh update --api` 可以直接指定。整个更新的时间不超过面板和 `cp.sh` 等待的 2100 秒：git 用掉的时间从备用线路的时间里扣。不登录每小时 60 次请求，一次最多下 50 个文件。要保留的路径由 `in_checkout()` 按 `SPARSE` 判断，和 git 的稀疏检出一致。
- 更新：一次只跑一个，`/status` 的 `updating` 说明正在做什么（面板显示「更新中」）；分三步：拉提交；把改动的文件内容下载到临时目录（手机上的仓库是按需下载的，这一步才是大头）；本地切换代码。前两步速度低于 1 KB/s 满一分钟就放弃这一次，网络问题会再试一次（每次用新的临时目录）；下载被打断不会留下换了一半的代码。GitHub 上没有新提交时跳过下载；代码、手机端文件、浮窗、服务本身都没变时回答「已是最新」，不重启脚本（上一次更新换了代码却没来得及重启脚本的，这次补上）。超时的 git 先收到 SIGTERM（它自己清理锁文件），不行才 SIGKILL；更新开始时清掉上次中断留下的临时目录和 `.git` 里遗留的锁文件（`*.lock`）：锁只可能被正在运行的 git 持有，所以手机上没有 git 在运行时全部清掉（清点之后被别的 git 新建的不动），有 git 在运行（包括 fetch 留在后台的整理进程）时一个都不动。`cp.sh code --github` 遇到服务在运行就交给服务更新（`/update?force=1`）：服务正忙（在更新或在重启）就等，最多 15 分钟；没更新成功以失败退出；服务进程在但不应答时不自己动仓库。代码目录同一时刻只有一个写入者。`cp.sh code`/`setup` 把电脑上的代码放到手机时，在 `/ip/local_code` 记下这份代码的时间；GitHub 上最新提交比它旧（还没推送）就不更新，`cp.sh update --force` 除外。服务拉代码后，自己的代码变了就重启自己（比较的是正在运行的代码；新的 supervisor.py 先在子进程里试加载，加载不了（语法错误、导入失败）就不重启，旧服务照常运行，只把脚本重启到新代码，并记住这一版：它不变，以后的更新就不再为它重启脚本），`cloudphone/app/panel.apk` 变了就通过本机 adb 装新浮窗（`/ip/panel.apk.sha` 记着装的是哪个，`cp.sh app` 也写它）。`cp.sh code`/`setup`/`code --github` 推来新的 supervisor.py 时，正在运行的服务会被安全重启；`cp.sh restart` 把本机的 `phone/restart.sh` 推到手机的 `tmp/` 下运行（和 `cp.sh` 版本一致，不覆盖手机自己的那份）：找到正在运行的服务（`supervisor.pid` 丢了就按命令行找），每 10 秒重发一次停止信号，旧服务退出后启动新的；10 分钟后旧服务还没退出，就转到手机后台继续等（最多一小时），命令以退出码 3 结束。

## cp.sh 命令
| 命令 | 作用 |
|---|---|
| `all` | 新手机：setup + code --github + app + up |
| `setup` | 装 proot、Alpine、Python/opencv/tesseract/adb/git（装过的跳过） |
| `code [--github]` | 把本地代码推到手机（测试没推送的改动）；`--github` 让手机自己拉 origin/main |
| `app` | 编译（源码变了才编）并安装浮窗 |
| `up` / `restart` | 启动服务和浮窗 / 重启服务（脚本会接着跑） |
| `scripts` `status` `log [N]` `start ID` `stop` `update` | 控制服务 |
| `try 参数...` | 测试：先停掉服务正在跑的脚本，在前台跑一次 `python3 -u 参数 --adb 127.0.0.1:5555 --delay 0`，再把原来的脚本启动回来 |
| `peek [比例]` | 手机屏幕 JPEG（手机上压缩，~1 秒） |
| `pull 路径` | 手机上的图片（例如 debug 截图）转 JPEG 拉回 |
| `sh 命令` | 在手机的 Alpine 里执行（当前目录 /ip） |

## 文件
- `phone/`：放到手机 `/data/local/tmp/ip` 的文件：`setup.sh`（装环境）、`run.sh`（进 Alpine）、`start.sh`（启动服务）、`restart.sh`（等旧服务安全停下再启动新的）、`supervisor.py`、`scripts.json`（默认的脚本列表；另一个号的是 `scripts.号名.json`）、`peek.py`/`jpg.py`（调试截图）。
- `app/`：浮窗 App（Java，无 Gradle，`build.sh` 编译；第一次会下载约 150 MB 的安卓编译工具到 `app/.sdk`）。`panel.apk` 一起提交，换电脑不用重新编。
- 手机上：`/data/local/tmp/ip/app`（代码，GitHub 稀疏检出）、`logs/`（每个脚本的日志、服务日志）、`state.json`（重启后接着跑哪个脚本）。

## 已知情况
- 红手指禁止安装 Termux；UserLAnd 2021 版拉不到应用列表。现在的方案只用 adb shell 用户 + proot。
- 从 Mac 远程截原图很慢（~13 秒/张，走 Tailscale 中转），调试一律用 `peek` / `pull`。
- 模板用 Mac 那套（`pics/mac/zone`），截图按宽度缩放到 Mac 参考尺寸（993.8），720p 上匹配分数 ≥ 0.98，不用重截。
